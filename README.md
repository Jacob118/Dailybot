# DailyBot 本地 Agent

DailyBot 是一个运行在本机的二游工具控制台原型。它提供本地网页界面，用来保存游戏和日常工具路径、按顺序检查并启动游戏与工具，并查看工具进程退出状态与日志。

## 启动

从源码运行需要 Python 3.10 或更新版本。没有安装 pywebview 时会使用系统浏览器；构建环境安装了 pywebview 时会打开桌面窗口。普通用户不应安装 Python；发布给用户时应提供独立的 `DailyBot.exe`。

当前源码可以在 Windows 双击 `启动 DailyBot.bat`，也可以在项目目录打开终端运行：

```powershell
py -3 app.py
```

macOS / Linux：

```sh
python3 app.py
```

使用浏览器运行时打开 <http://127.0.0.1:8765>。关闭运行窗口会停止 Agent。

## 构建 Windows 独立程序

在 Windows x64 的开发电脑上安装 Python 3.10 或更新版本，然后双击 `build-windows.bat`。脚本会安装构建工具并生成 `dist-detection\DailyBot.exe`，其中包含 Python 运行时、桌面窗口组件和网页文件。将这个 exe 发布给用户后，用户无需安装 Python。用户双击 EXE 后会直接打开 DailyBot 桌面窗口，不需要通过浏览器访问。Windows 需要 WebView2 Runtime；如果缺少，需先安装 Microsoft WebView2 Runtime。构建脚本只用于开发和发布，不是用户启动程序的入口。

## 连接工具

DailyBot 启动时会检查已保存的程序路径和自己下载的工具；点击“检测本机工具”可重新查找。BetterGI 和 OK-WW 会尝试从 Windows 已安装程序记录中定位。MAA、MaaEnd 等便携版若解压在 DailyBot 管理目录之外，系统没有统一的安装记录，可能无法自动找到；此时在“连接工具”中点击“浏览”选择 `.exe` 即可，无需移动工具目录。DailyBot 不会递归扫描整台硬盘。

每个游戏卡片都有“下载安装”按钮和官方发布页入口。下载安装功能目前要求 Windows 10/11 x64：DailyBot 从各项目的 GitHub 最新稳定版下载对应官方文件，并显示下载进度。

- MAA 使用官方 x64 ZIP 包；下载后检查压缩包路径并解压到 `%LOCALAPPDATA%\DailyBot\tools`，随后自动填写 MAA 程序路径。
- MAAEnd 使用官方 Windows x64 ZIP 包；下载后检查压缩包路径并解压，随后自动填写 `MaaEnd.exe` 程序路径。MaaEnd 自身支持一键日常预设和新版本自动更新。
- BetterGI 下载官方安装程序并启动安装向导。完成向导后，点击“连接工具”填写 BetterGI 程序路径。
- OK-WW 先选择中国服或国际服，再下载并启动对应官方安装向导。完成向导后，点击“连接工具”填写 OK-WW 程序路径。

文件保存在 `%LOCALAPPDATA%\DailyBot\downloads`。DailyBot 会显示发布版本与文件名；GitHub 发布信息含 SHA-256 时会比对校验，没有提供时会计算并展示文件 SHA-256。用户可在下载或解压时取消。下载只从固定的官方 GitHub 项目获取，不会上传到 DailyBot 服务器。安装程序会正常显示，由用户完成其安装向导。macOS 和 Linux 版本会显示 Windows 平台提示，不会执行 Windows 安装程序。

如果选择自行安装，也可以从官方发布页下载，然后点击“连接工具”填写程序完整路径。可选参数每行填写一个；没有参数就留空。比如 OK-WW 有自己的一条龙命令行参数，可以按它当前版本的说明填写。

每款游戏的“编辑设置”中可以另外选择游戏本体的 `.exe` 路径。运行队列时，DailyBot 会先按游戏常见进程名检查游戏；已经运行就继续启动对应工具。没运行且填写了游戏程序路径时，DailyBot 会直接打开该游戏并等待进程出现，最长等待 120 秒；没填写路径则停止并提示手动启动游戏或补充路径。请选游戏本体，不要选启动器。游戏启动后，前一个工具进程正常退出才会进入下一项；任何工具返回非零退出码，队列会停止。最长工具运行时间可以在单个工具设置里调整。

这个进程检测适用于 Windows 上的游戏程序。若明日方舟或终末地运行在安卓模拟器内，Windows 只能看到模拟器程序，不能据此确认模拟器内部的游戏是否启动；当前版本不会把“模拟器已打开”误报成“游戏已启动”，这类情况需要单独接入 ADB。

这个原型负责检查和启动游戏程序，并启动、跟踪普通 Windows / macOS 工具进程。DailyBot 可以启动 MaaEnd，但目前不会操作 MaaEnd 界面或触发它内部的日常预设；需要在 MaaEnd 自己的界面中选择并启动任务。DailyBot 不会识别游戏画面，也不能判断是否已经登录、加载完成或完成每日任务。界面里的“工具已退出”表示进程已正常结束，不等于游戏内任务已确认完成。

明日方舟的安卓模拟器流程可以选配 MAA 命令行程序：在“编辑设置”中选择单独安装的 MAA CLI 命令行 `.exe`（不要选择 MAA 图形界面程序），并选择客户端类型。运行时 DailyBot 会先执行 `maa startup <客户端类型>`，最多等待 10 分钟；成功后再打开已连接的 MAA 图形界面。MAA 命令行版需要单独安装 MaaCore/资源并初始化连接配置，它的配置与 MAA 图形界面配置分开管理。没有配置命令行程序时，仍使用上面的 Windows 游戏程序检测和启动方式。

MAA CLI 集成只负责启动模拟器/客户端并进入游戏，不会替你启动 MAA 里的日常任务。DailyBot 也没有识别游戏画面、判断每日任务是否完成的能力。界面里的“工具已退出”表示进程已正常结束，不等于游戏内任务已确认完成。

## 本机数据

Windows 会将配置和日志存到 `%LOCALAPPDATA%\DailyBot`；macOS / Linux 存到 `~/.dailybot`。删除这个目录会移除 DailyBot 保存的配置和日志。游戏登录态仍由各自的游戏或工具管理。

Agent 只绑定 `127.0.0.1`，不会监听局域网或公网，也不接受云端指令。平时不会联网；只有用户点击“下载安装”时，才会连接 GitHub 读取官方发布信息和下载文件。请只填写你信任的程序路径；启动参数会原样传给该程序，不经过命令行 Shell。

## DailyBot 更新检查

DailyBot 启动时会连接 GitHub 检查自身是否有新版本，也可以点击“检查更新”手动检查。发现新版后会提供 GitHub Release 入口，由用户下载并替换程序；更新检查失败不会影响工具运行。

## 当前不包含

- 自动定时执行、通知或云端调度
- 游戏账号密码或登录态管理
- 游戏画面状态读取、登录/加载确认和任务完成验证
- 安卓模拟器内部的游戏进程检测与启动（需要 ADB 接入）
- MAA、MaaEnd、BetterGI、OK-WW 逐个版本的任务配置或专用自动化接口
